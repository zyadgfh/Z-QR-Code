# تقرير الأمان — QR Menu (تدقيق ‎/ancs‎ + ‎/cfsa‎)

تدقيق أمني شامل للمنتج بأكمله: نموذج التهديد، المراجعة اليدوية لكل سطح هجوم، الإصلاحات المطبقة، والاختبارات التي تثبتها. التاريخ: 2026-11-21 — النسخة المدققة: ما بعد PR الأمان (بوابة الإعداد الأول + تغيير كلمة المرور + الترويسات الأمنية).

---

## 1. نموذج التهديد (خلاصة)

| الجهة الفاعلة | ماذا يريد | السطح |
|---|---|---|
| زبون فضولي | طلبات بأسعار ملفقة، رؤية طلبات غيره | `POST /orders`, `GET /orders/:id` |
| موظف ساخط | تعديل المنيو، رؤية الاشتراك | `/api/shop/*` بدور staff |
| مالك محل منافس | قراءة/كتابة بيانات محل آخر | كل نقاط `/api/shop/*` |
| مهاجم خارجي | تخمين كلمات مرور، سبام طلبات، تسريب المفاتيح | `/login`, `/orders`, المتصفح، السجلات |
| متصفح عام | الاتصال المباشر بـ Firestore/Storage | قواعد Firebase |

## 2. الضوابط المفروضة ومكان فرضها

### المصادقة والجلسات
- **scrypt** لتخزين كلمات المرور (ملح 16 بايت لكل مستخدم) — لا تخزين نصي أبدًا (`server/lib/auth.js`)
- **JWT HS256** بتوقيع سر الخادم، صلاحية 14 يومًا، فحص توقيع بـ `timingSafeEqual` ضد هجمات التوقيت
- مقارنة كلمات المرور أيضًا بـ `timingSafeEqual` بعد مساواة الطول
- **بوابة الإعداد الأول** `POST /api/auth/bootstrap-admin`: تعمل فقط عند انعدام أي حساب أدمن، ثم 403 نهائيًا (`ALREADY_INITIALIZED`) — تمنع تكتيك «أسر أول حساب» وتلغي الحاجة لكلمات مرور بذرية عامة. حد معدل 5/دقيقة + كلمة مرور 10 أحرف إدارية
- **تغيير كلمة المرور** `PUT /api/auth/password` يتطلب كلمة المرور الحالية (مقارنة توقيت-آمنة) + 8 أحرف

### الأدوار والعزل (أهم ضابط)
- الأدوار ثلاثة (`owner` / `staff` / `platform_admin`) تُفحص **في الخادم** عند كل نداء — الموظف يرى الطلبات فقط (`403` مفروض وليس إخفاء أزرار، مختبر)
- عزل المستأجرين في نقطة واحدة: كل دالة خدمة تتحقق `doc.shop_id === req.member.shop_id` — أي وصول لمستند محل آخر يرد **404 بلا كشف وجوده** (8 حالات اختبار: قراءة/كتابة/حذف/قبول طلب عبر محل)
- أدمن المنصة يمر عبر حارس دور منفصل في `/api/admin/*`

### سلامة الطلبات والمال
- **إعادة حساب الإجمالي من قاعدة البيانات فقط** — أي `price`/`line_total` يرسله العميل يُهمَل تمامًا (اختبار تلاعب صريح)
- التحقق الكامل: الترابيزة داخل `1..table_count`، الصنف موجود/متاح/يخص المحل، الخيارات صحيحة ومربوطة بالصنف، حدود الاختيار الواحد/المتعدد/الإجباري، الكمية 1..10، الحد الأقصى 30 سطرًا
- دقة مالية بفلسات (تقريب `Math.round(n*100)/100`) — اختبار عشري 41.25

### حدود المعدل (مضادة للسبام والتخمين)
- `POST /orders`: **10/دقيقة لكل IP** (نطاق زبائن — سبام الطلبات سداده)
- `POST /login`: **10/دقيقة لكل IP** (تخمين كلمات المرور)
- `bootstrap-admin`: **5/دقيقة**
- مفتاح العداد يشمل هوية نسخة التطبيق (`qm_app_id`) فلا تتلوث العدادات بين النسخ
- ⚠️ ملاحظة موثقة: على Vercel serverless العدادات تقريبية لكل نسخة دافئة — الخدمة الوحيدة الحساسة للاستمرارية هي `login`، والحصانة تأتي من قوة كلمات المرور + الـ JWT. عند الحاجة لحماية صارمة عابر للنسخ: CF Rate Limiting (انظر §6) أو Upstash Redis لاحقًا.

### الملفات والمدخلات
- رفع الصور: `POST /api/shop/uploads` — مالك فقط، **data URL بمحدد MIME صارم** `^data:image/(jpeg|png|webp);base64,$`، حد 4MB، رفع للخادم فقط (المتصفح ممنوع كتابةً في قواعد Storage)
- تحليل JSON بحد 4MB (`express.json`) — الرفوض يرد 413
- لا تنفيذ قوالب/استعلامات نصية: كل استعلامات Firestore بمعاملات مهيكلة (`where(field, '==', value)`) — سطح NoSQL injection غير موجود بالتصميم
- XSS: React يهرّب المخرجات افتراضيًا + لا `dangerouslySetInnerHTML` في المشروع كله

### تكوين المنصة والترويسات (إصلاحات هذا التدقيق)
- `x-content-type-options: nosniff` · `x-frame-options: SAMEORIGIN` · `referrer-policy: strict-origin-when-cross-origin` · `permissions-policy` (إيقاف الكاميرا/الميك/الموقع) · `strict-transport-security` عند HTTPS — على كل الردود (`server/app.js`)
- `trust proxy 1` — تحديد المعدل يعمل بالـ IP الحقيقي خلف Render/Vercel
- CORS مفتوح افتراضيًا لنطاق الواجهة نفسها فقط؛ `CORS_ORIGIN` لفصل النطاقين
- `x-powered-by` معطّل
- **المفاتيح**: كل الأسرار في متغيرات البيئة مشفرة على Vercel، لا شيء في الكود؛ نداء Gemini يرسل المفتاح في ترويسة `x-goog-api-key` (لا يظهر في السجلات/الروابط)؛ `.env` مستثنى من Git
- service account صلاحياته عبر Admin SDK من الخادم فقط، وقواعد `firestore.rules`/`storage.rules` تمنع المتصفح كليًا (قراءة عامة للصور فقط عبر روابطها)

### الذكاء الاصطناعي (سطح جديد يحتاج ذكرًا)
- مدخل المستخدم: **صور** فقط (بيانات base64 بحد 4MB ونوع محدد) — لا نص حر يمر للنموذج
- المخرجات: مقيدة بـ `responseSchema` (JSON منظم) ثم تُطبَّع وتُقشر (`normalizeDraft`) — لا شيء يُنشر دون مراجعة المالك يدويًا، ولا يلمس الـ AI قاعدة البيانات إطلاقًا
- حد التكلفة: 3 صور/نداء، ونداء المالك فقط — تكلفتها في الطبقة المجانية لـ Gemini

## 3. قرارات أمنية مقصودة (قابلة للنقاش)
- **روابط QR عامة بالتصميم**: منيو المحل عام لكل من يمسح الكود — لا سرية للمنيو، والطلب لا يتطلب حساب زبون (خصوصية: لا نجمع أي بيانات شخصية — لا اسم/هاتف زبون، مطلوب في المواصفات)
- **معرف الطلب UUIDv4**: غير قابل للتخمين إحصائيًا؛ متابعة حالة الطلب تحتاجه فقط (اختبار 404 لمعرف عشوائي)
- طلب الزبون المعلق يبقى صالحًا رغم رسالة الانشغال (قرار مواصفات §6.3)

## 4. الاختبارات المثبتة (30/30)
عزل المستأجرين (8 هجمات) · تلاعب الأسعار والخيارات · رفض المحل المقفل على مستوى API · صلاحيات الموظف/الأدمن من الخادم · تسريب المراحل للعميل = صفر · حدود المعدل (429) · بوابة الإعداد: إغلاق نهائي + كلمات ضعيفة مرفوضة · تغيير كلمة المرور بدورة كاملة · **جديد**: الترويسات الأمنية على كل الردود + رفض جسم 4MB+ (413)

## 5. نتائج التدقيق — ما تم إصلاحه في هذه الجلسة
| # | النتيجة | الخطورة | الإصلاح |
|---|---|---|---|
| 1 | غياب ترويسات الأمان على الردود | متوسط | middleware الترويسات في `app.js` + اختبار |
| 2 | حد JSON 8MB أكبر من الحاجة | منخفض | خفض إلى 4MB + اختبار 413 |
| 3 | كلمات مرور بذرية عامة في مستودع عام | **عالٍ** | بوابة bootstrap تُغلق بعد أول أدمن + إلغاء توصية seed في الإنتاج |
| 4 | مفتاح Gemini في رابط النداء (يظهر في السجلات) | متوسط | ترويسة `x-goog-api-key` |
| 5 | لا آلية تغيير كلمة مرور (قرار مالك دائم بقائمة عامة) | متوسط | `PUT /api/auth/password` لكل الأدوار |

## 6. توصيات مستقبلية (غير مثبتة بعد — بترتيب الأثر)
1. **Cloudflare أمام الموقع (‎/cfsa‎ بالمعنى العملي)**: DNS ببروكسي برتقالي + WAF Managed Rules + Rate Limiting على `/api/auth/login` و`/api/public/*/orders` عابر للنسخ + Bot Fight Mode + التخزين المؤقت للملفات الثابتة. لا يتعارض مع Vercel (DNS فقط يتجه لـ CF ثم origin لـ Vercel) — خطوة إعداد حسابية بلا كود
2. تدوير `JWT_SECRET` بكتابة فوقه في متغيرات المنصة (يسجل خروج الجميع)
3. تدوير مفتاح Gemini وservice account دوريًا (زر إعادة التوليد في لوحة كل مزود)
4. تدقيق تبعيات دوري: `npm audit` + Dependabot على المستودع
5. نسخ احتياطي مجدول لـ Firestore (PITR أو export مجدول) — بيانات مالية للمحلات

## 7. حد المرض الصادق
الحدود الوحيدة التي لم نضعها: لا 2FA (حسابات المالك/الأدمن)، ولا قفل حساب بعد X محاولة (الحد الأدنى 10/دقيقة + كلمات مرور قوية يعوضان في v1). كلاهما مرشح طبيعي للنسخة القادمة إن نما عدد المحلات.
